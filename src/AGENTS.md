# Клиентские инструкции для агентов

Перед изменениями прочитай корневой `AGENTS.md`; этот файл дополняет его
правилами клиентского слоя.

## Границы ответственности

- Клиент отображает серверное состояние и отправляет пользовательские
  намерения. Не реализуй на клиенте правила размещения, подсчёт очков,
  допустимость фишек или другие игровые решения.
- Взаимодействие с Socket.IO проходит через `modules/GameService.ts`.
  Команды, влияющие на состояние, используют ack-ответ и ограниченный таймаут;
  широковещательный `gameUpdated` — только для синхронизации отображения.
- Событийные слушатели и таймеры должны удаляться при смене контекста или
  размонтировании. Не регистрируй повторные слушатели при каждом обновлении
  состояния.
- Типы домена импортируй из `@server/*`; типы Socket.IO и UI-специфичные
  состояния размещай в `src/types/`.

## Синхронизация

- Для поворота сообщай серверу только угол поворота; не отправляй обратно
  целый объект тайла как авторитетное состояние.
- После команды показывай ошибку через `notifyError`/`notificationService` и
  синхронизируй локальное превью с последним серверным состоянием.
- Не жди общего `gameUpdated` как подтверждения собственной команды: событие
  может относиться к другому игроку или параллельному обновлению.
- При изменении Socket.IO payload обновляй серверный обработчик,
  `src/modules/GameService.ts`, `src/types/socket.ts`, тесты клиента и
  справочник событий в корневом `AGENTS.md`.

## Проверка изменений

- Клиентские проверки: `pnpm run type-check`, `pnpm test`, `pnpm run build`.
- Для поведения транспорта добавляй интеграционный тест
  `tests/integration/clientGameService.test.ts`.
- `pnpm run lint` только проверяет; автоматическое исправление запускается
  отдельной командой `pnpm run lint:fix`.
