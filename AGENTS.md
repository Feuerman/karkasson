# Инструкции для агентов и контрибьюторов

Проект — онлайн-игра «Каркассон»: Vue 3 SPA в `src/`, сервер Node.js/Socket.IO
в `server/`, сохранение игр в Firebase Realtime Database. Пакеты управляются
pnpm workspace. Обзор архитектуры и запуск описаны в [README.md](README.md),
история релизов — в [CHANGELOG.md](CHANGELOG.md).

## Основные инварианты

- Игровое состояние и правила принадлежат серверу. Клиент отображает
  `gameUpdated` и отправляет пользовательские намерения; не переносить на него
  валидацию ходов или подсчёт очков.
- Единственная доменная модель — `server/src/modules/types.ts`, доступная
  клиенту через `@server/*`. Типы клиентского Socket.IO-контракта находятся в
  `src/types/socket.ts`.
- `server/src/socket/handlers/` — транспортный слой; `server/src/services/`
  управляет лобби, партиями и ИИ; `server/src/modules/GameManager.ts` содержит
  игровую машину состояний; `scoring.ts` — чистые функции подсчёта очков.
- Сервер не доверяет присланным клиентом объектам игры: заново разрешает
  тайл/объект из состояния партии и проверяет очередь и допустимость команды.
- Клиентские команды состояния используют ack через
  `src/modules/GameService.ts`; широковещательные события служат для
  синхронизации, а не для подтверждения собственной команды.
- Сохранения сериализуются через `server/src/modules/gameSave.ts`. При
  изменении формата поддерживай старые версии миграциями и тестами.
- Определения тайлов находятся в `server/src/data/tiles.ts`; клиентский
  `src/data/tiles.ts` переэкспортирует их. Не создавай вторую копию каталога.
- Для тайла сопоставляй стороны по именам направлений, не по порядку ключей
  `sides`. Координаты `rowIndex` — Y, `tileIndex` — X.

## Работа над изменениями

- Предпочтителен минимальный связный diff: не делать несвязанный рефакторинг и
  не менять публичное поведение сверх запроса.
- Если пользователь просит разобраться или оценить, не редактируй файлы без
  явного запроса на реализацию. Для реализации используй контекст задачи и
  локальные паттерны; не проси повторно сведения, уже доступные в репозитории.
- Перед реализацией изучи локальный код и следуй имеющимся паттернам. Повторно
  используй существующие решения; не добавляй абстракции без конкретной пользы.
- Для нетривиальной задачи сначала обозначь короткий план. Если требования
  противоречат архитектуре или неоднозначны и выбор меняет игровое поведение,
  протокол либо формат сохранений, уточни решение до спорной правки. В остальном
  выбери наименее рискованный вариант и продолжай.
- Для каждого изменения сопоставь затронутое поведение с тестами. Добавь или
  обнови проверки обнаруженных пробелов; сборка и проверка типов сами по себе
  не подтверждают поведение. Для документационных и конфигурационных правок
  проверь последствия и укажи в отчёте, если исполняемое поведение не менялось.
- Перед завершением задачи запусти `pnpm run type-check` и полный `pnpm test`.
  Также запускай проверки соответствующего слоя из таблицы ниже; линт и обе
  сборки обязательны, если изменения их затрагивают.
- Новый код — TypeScript без `any`, с осмысленными именами и небольшой
  ответственностью. Не используй non-null assertion (`value!`): проверь
  наличие значения или вырази гарантию типами.
- Не добавляй зависимость, пока не проверишь манифесты и существующие
  библиотеки. Для неизвестного или меняющегося API сверяйся с актуальной
  документацией.
- Отвечай пользователю по-русски и по существу. Сообщай о замеченной проблеме
  качества, если она относится к изучаемому или изменяемому коду.
- В итоговом сообщении кратко перечисли результат, важные затронутые области и
  фактически запущенные проверки; явно укажи, если проверки не запускались.

## Команды и проверки

| Команда | Назначение |
| --- | --- |
| `pnpm run dev` | Vite dev-сервер клиента |
| `pnpm --filter server run dev` | сервер с nodemon |
| `pnpm run type-check` | `vue-tsc --noEmit` |
| `pnpm test` | полный набор Vitest: unit и integration |
| `pnpm run test:gameplay` | две полные партии: 4 ИИ и человек против ИИ |
| `pnpm run test:browser` | браузерный smoke: лобби, слоты, запуск игры |
| `pnpm run lint` | ESLint, только проверка |
| `pnpm run lint:fix` | ESLint с автоисправлением файлов |
| `pnpm run build` | production-сборка клиента |
| `pnpm --filter server run build` | компиляция сервера (`tsc`) |

`pnpm run format` изменяет форматирование файлов Prettier. Не запускай его на
всём репозитории ради несвязанной правки.

### Проверки по областям

- Серверные правила/ходы: полный `pnpm test`,
  `pnpm --filter server run build` и клиентская проверка типов.
- Socket.IO-протокол: синхронно проверь серверный handler, клиентский
  `GameService`, `src/types/socket.ts` и сценарий в
  `tests/integration/clientGameService.test.ts` или другом интеграционном
  тесте через `TestClient` и `createGameServer`.
- Сохранения: проверь unit round-trip/миграции и
  `tests/integration/persistence.test.ts`.
- Клиент: `pnpm run type-check`, `pnpm test`, `pnpm run build`; поведение
  транспорта покрывай интеграционным тестом.
- Интеграционные проверки запускают настоящий сервер и Vite.
  `computerOnly.test.ts` проверяет полную партию четырёх ИИ, а
  `scoring.test.ts` — полную партию человека с ботами и инварианты очков и
  фишек. `pnpm run test:gameplay` запускает обе партии без остальных тестов;
  используй его как дополнительную быструю регрессионную проверку после
  изменений игрового процесса. Он не заменяет обязательный полный `pnpm test`.
- `pnpm run test:browser` запускает Playwright smoke реального UI. Требует
  установленный Chromium (`pnpm exec playwright install chromium`); серверные
  правила и полные партии по-прежнему проверяются Vitest-интеграциями.

## Точки расширения

  `src/modules/GameService.ts`, серверный обработчик в
  `server/src/socket/handlers/` и интеграционную проверку.
- Новое игровое правило/объект: проверь доменные типы, `GameManager`, подсчёт,
  симуляцию ИИ, доступные размещения, отображение и unit/integration-тесты.
- Новый тип фишки: обнови `FollowerType`, пулы `FollowerCount`, серверную
  валидацию реального и симулируемого хода, клиентский выбор и тесты.
- Изменение протокола сохранений: обнови версию схемы и миграции в
  `gameSave.ts`, тесты unit и восстановления/перезапуска.

## Соглашения репозитория

- Prettier: без точек с запятой, одинарные кавычки, 2 пробела,
  `trailingComma: es5`, `printWidth: 80`. ESLint настроен в `.eslintrc.json`.
- Алиасы: `@/*` → `src/*`, `@server/*` → `server/src/*`.
- UI использует Nuxt UI v4 и токены Tailwind в `src/assets/main.css`;
  уведомления — через `src/plugins/notification.ts`, не напрямую через
  `useToast()`.
- Сообщения коммитов — на русском, с принятым префиксом области (`Server`,
  `Client`, `Changelog:`); Conventional Commits не используются.
- Продуктовые изменения сопровождаются записью в CHANGELOG и SemVer-версией
  корневого `package.json` перед релизным push. Документация, tooling и
  обслуживание без влияния на продукт могут не требовать релиза.
- Локальный `.env.local` игнорируется Git; не коммить секреты. Не добавляй
  ключи и токены в Firebase-конфигурацию.
